# 价值投资研究工作台（NocoBase 本机版）

一句话：**一个可复用的价值投资研究数据库**，同时研究五家公司——长江电力（600900.SH）、太阳纸业（002078.SZ）、中国建筑（601668.SH）、腾讯音乐（01698.HK）、小米集团（01810.HK）。研究链条固定为「来源 → 事实 → 论点 → 假设 → 估值 → 跟踪」，换公司只换数据，不换结构。

本目录（`二级市场/价值投资/`）是一个完整项目：各公司文件夹放**研究材料与给人读的报告**；**程序和数据在 `nocobase/`**（PostgreSQL 存数据，脚本生成表、公式和页面；2026-10-25 从 `~/Desktop/二级市场/价值投资/nocobase` 迁入）。两边不是两份数据，各公司文件夹里的手册都是副本或旧记录，**以数据库为准**。

## 一、怎么打开

```sh
cd ~/Desktop/二级市场/价值投资/nocobase
docker compose up -d          # 先启动 Docker Desktop
```

- 网站：http://localhost:13000 （只监听本机），管理员 `admin@nocobase.com`
- 关电脑、休眠或 Docker 没启动时，网站和采集都不工作；错过的定时点不补跑
- 备份：`./backup.sh`（整库到 `backups/`）；临时查库：`./psql.sh -c "select ..."`
- 停用：`docker compose stop`

首次进入看「驾驶舱」，再看「商业模式 → 核心论点 → 假设依据 → 估值结论」这条主链。

## 二、库里有什么

每家公司一个顶层菜单，各有一套同样的页面：

| 分组 | 页面 |
|---|---|
| 顶层 | 驾驶舱（关键读数、立即采集按钮、图表） |
| 商业模式 | 商业模式拆解、产业链与五力（含竞争对手）、竞争壁垒、风险分析、价投适配度、核心论点；可视化与明细编辑分标签 |
| 数据底稿 | 只放事实：数据（指标＋数值：公司披露的经营数字 ｜ 自动采集的行情、利率、水位）、财务数据、事实摘录、来源文档 |
| 预测与估值 | 历史年度 → 财务模型 → 估值 → 模型底稿。长江电力保留原定制页面；其余四家在财务模型内编辑逐年假设，假设依据、估值模型和情景在模型底稿。腾讯音乐和小米保留分部加总为主估值，分部与资产项目在估值页内编辑 |
| 跟踪 | 自动检查、问题清单、跟踪事项、变更日志 |
| 另外 | 顶层「宏观数据」（利率、汇率、商品，各公司订阅）；「框架与后台」（使用说明、数据结构、模型公式、公司、指标、采集） |

后台规模：27 张基础表、21 张关联表、55 个视图（视图＝输入列＋公式列）。每张表分三层：`vi_<表>_base`（真实存储）、`vi_<表>_calc`（计算列）、`vi_<表>`（界面视图，写入由触发器落回 base）。字段定义在 `framework/spec.py`，SQL 由它生成，不要手改数据库结构。

## 三、数据怎么连起来

```
来源文档 ──> 事实摘录 ──> 商业模式拆解 / 产业链 / 竞争对手 / 竞争壁垒 / 风险分析
                  │                        │
                  └──> 核心论点 <───────────┘（壁垒与适配度都靠论点裁决）
                            │
                       假设依据 ──> 逐年假设 ──> 预测计算 ──> 估值结论
                                                      └──> 分部加总 / 敏感性 / 试验
```

三条硬规矩：

1. **同一事实只存一次**（`事实摘录`），其它表通过关联引用；一条事实平均被 4 张分析表引用。建立引用**不会**自动改估值数字。
2. **空白＝未知，不是 0**；现金流缺项时宁可不输出价值。比率一律存小数（0.052＝5.2%），金额单位亿元。
3. **派生值不手填**：单价、派息率、税率、利息、每股价值、检查结果都由公式算；模型表永不出现股价。

## 六、改东西之前

- **改数据**：在页面里改，或改 `companies/<代码_名称>/analysis.py`/`seed.py` 后重新生成 `seed.sql` 并执行（按业务键引用，可重复执行，只影响本公司）。
- **改结构或公式**：`framework/gen_sql.py` → `sql/01_schema.sql`（或写迁移）→ `02_calc.sql`、`03_ui.sql` → `register.py` → 重启 app → `build_pages.py`。顺序错了会出现字段说明与页面不一致、关联字段加载失败等问题，坑清单见 `framework/README.md`。
- **改页面**：`build_pages.py` / `build_overview.py` / `build_finmodel.py` / `build_chainmap.py` / `build_fitboard.py`，不要只在界面上点（重建页面会覆盖）。改前先 `./backup.sh`。
