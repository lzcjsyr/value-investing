# 前后台表格映射核验

> 后续进展（2026-10-25）：本文核验出的四类集合名称差异已按前端名称完成统一；下方名称差异表保留为修改前记录。其他页面与字段问题仍按原核验结果理解。

核验日期：2026-10-25。数据源 `main`；以当前管理员可访问的桌面页面为范围。本次只读核验，未修改数据库、集合或页面配置。

## 结论

**业务对象与记录对应完整，前后台命名、字段展示和公司页面还没有完全统一。**

- 27 张业务基础表均有同名代码的接口视图，且全部有前端表格入口。27 对表逐一核对记录数、ID 集合与视图 ID 唯一性，均一致。
- 前端实际使用 33 类业务集合：27 类输入对象＋6 类计算报表。33 类都有对应的 NocoBase 集合，没有孤立的业务表格来源。
- NocoBase 登记 56 个集合，另 23 个是 21 张隐藏关联表和用户、角色 2 个系统集合，不属于研究业务维护页面。
- 页面共有 145 个主表格区块，分布于 144 个页面。五家公司、宏观和后台页面按不同范围重复使用共享集合；这些区块不是 145 张独立存储表。157 个页面中的其余 13 页为驾驶舱、财务模型可视化和说明文档。

## 距离统一还有哪些差异

### 1. 四类常规业务表的名字不同

| 后台集合名称 | 前端页面名称 |
|---|---|
| 商业模式 | 商业模式拆解 |
| 价值投资适配度 | 价投适配度 |
| 历史财务（年度） | 财务数据 |
| 定期经营数据 | 经营数据 |

此外，“高频数据（全部指标）”用于标明后台全量范围；长江电力的竞争对手表放在“产业链与五力”页。它们属于范围或组合展示差异，未重复算作上述四类常规改名。

### 2. 一处页面合并，四个公司入口未建

- 长江电力“产业链与五力”页面放了产业链、竞争对手两张表；其他四家公司仍是两个独立页面。若要求一表一页，此处需拆成两页。
- 风险分析目前只有长江电力页面。太阳纸业、中国建筑、腾讯音乐、小米集团少 4 个同结构入口；这四家当前也没有风险表记录，属于模块尚未铺齐。

### 3. 主表默认列与基础字段不相同

27 张输入表共有 346 个原始业务字段（剔除 ID、创建时间和修改时间；关联选择按其外键对应一个字段）。主表默认显示其中 185 个，另外 161 个没有作为默认列列出。这个数按业务表类型去重，不将五家公司重复计数。

这 161 个字段中包含公司归属、来源、详细说明与模型输入，很多在新增或编辑弹窗中维护；“默认列不显示”不等于字段不存在或数据丢失。

同时，17 类输入接口视图比基础表多出 92 个计算字段，例如财务比率、单价、检查结果。27 个接口视图都没有输出基础表的创建时间 `created_at`；其余基础列全部输出并登记。

### 4. 详情模板有真实的字段展示缺口

12 类业务表的主表“查看”详情模板合计未显示 24 个原始业务字段。核验使用当前主表实际引用的共享详情模板，而非仅根据字段定义推测。

| 业务表 | 详情未显示的原始字段 |
|---|---|
| 公司 | 股价汇率指标（ID）（`price_fx_metric_id`） |
| 来源文档 | 发布日期（`publish_date`）；获取日期（`retrieved_on`） |
| 事实摘录 | 截至日期（`as_of`） |
| 竞争对手 | 截至（`as_of`） |
| 核心论点 | 辩论日期（`debated_on`） |
| 定期经营数据 | 期末日期（`period_end`） |
| 高频数据 | 观察日期（`obs_date`） |
| 估值模型 | 期初归母权益（亿元）（`opening_equity`）；期初长期股权投资（亿元）（`opening_lt_invest`）；期初少数股东权益（亿元）（`opening_minority`）；期初经营性长期资产（亿元）（`opening_op_assets`）；主估值方法（`primary_method`）；要求收益率（`required_return`）；无风险利率日期（`rf_date`）；分部加总·资产负债日（`sotp_as_of`）；分部加总·核心盈利调整（亿元）（`sotp_core_adj`）；分部加总·核心盈利年份（`sotp_year`） |
| 情景 | 情景概率（`probability`）；新增投资回报率（`ronic`）；合理倍数（手填）（`sotp_multiple`） |
| 分部估值项 | 截至（`as_of`） |
| 变更日志 | 日期（`change_date`） |
| 采集运行 | 公司（ID）（`company_id`） |

例如，“经营数据”的期末日期在主编辑表单中存在，在详情中未显示；估值模型的主编辑表单较完整，详情及其旧嵌套编辑弹窗仍少了一组后来增加的字段。来源文档的发布日期、获取日期也存在这种差异。

另有一个表单对齐点：采集运行的 `company_id` 已存在于基础表、接口和元数据中，源定义也有“公司”关联，但当前普通新增/编辑表单未展示该选择；驾驶舱按钮会自动写入公司范围。它已包含在上述 24 个详情缺项中，不重复计算为新的原始字段。

## 建议的对齐目标

1. 把 27 类输入对象作为维护目录，各有明确且同名的前端表格；五家公司继续按公司范围查看共享数据。
2. 将 6 类计算结果单列为报表，输入表中的计算列明确标为自动计算。
3. 统一四类名称，补齐四个风险分析入口，并统一长江电力的两表组合方式。
4. 详情展示全部原始业务字段，主表保留关键列；先补上述 24 个详情缺项，并补采集运行的公司选择。
5. 21 张关联表继续作为关联机制维护，在关系选择中体现，无需增加 21 个独立研究页面。
