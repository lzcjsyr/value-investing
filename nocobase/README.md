# 价值投资研究工作台（NocoBase 本机版）

在本机 Docker 中运行的 NocoBase＋PostgreSQL。数据结构是一套**可复用的价值投资框架**，现在研究五家公司：长江电力（600900.SH）、太阳纸业（002078.SZ）、中国建筑（601668.SH）、腾讯音乐（01698.HK）、小米集团（01810.HK），在菜单里分列为独立项目。飞书已停用（2026-10-21）。

## 启动与访问

```sh
cd ~/Desktop/二级市场/价值投资/nocobase
docker compose up -d      # 启动（需先运行 Docker Desktop）
docker compose stop       # 停止
./backup.sh               # 整库导出到 db/latest.sql（进 git）＋ backups/（本机历史）
./psql.sh -c "select * from vi_valuation"   # 直接查库
```

- 地址：http://localhost:13000 。只监听本机。
- 管理员：admin@nocobase.com。初始密码是 NocoBase 默认值，请在右上角个人设置里修改。
- 电脑关机、休眠或 Docker 未运行时，网站和定时采集都不工作；错过的定时点不会补跑。
- `storage/`（数据库本体）、`backups/`、`.env` 在 git 仓库目录里但被忽略，不上传 GitHub；上传的是导出文件 `db/latest.sql`，改完数据先 `./backup.sh` 再提交。恢复：`./psql.sh -f db/latest.sql`（会覆盖当前库；新库还要 `ALTER DATABASE nocobase SET jit = off`）。**不要执行 `git clean -fdx` / `-X`**，会把整个数据库删掉；挪动目录前先 `docker compose down`。

## 自动采集

**手动**：驾驶舱的「立即采集一次」按钮，一次跑完 采集 → 入库 → 自检（约 5—30 秒），每次都记在「框架与后台 / 采集 / 采集运行」。按钮只采这家公司的数据源和通用指标（如中债 10 年；港元汇率只在用它折算股价的港股公司里采），其他公司在各自驾驶舱里采；逻辑在 SQL 函数 `vi_collect_targets(运行)`，采集运行的“公司”留空时采全部。按钮靠工作流 ④ 运行，④ 已启用；它只在按按钮时运行。

**定时**（目前停用）：在「设置 → 工作流」中启用 ①②③：

| 工作流 | 时间 | 作用 |
|---|---|---|
| ① 采集 · 所有启用的数据源 | 每天 18:30 | 遍历“采集配置”，抓取原始响应 |
| ② 入库 · 校验去重写入高频数据 | 每天 18:40 | 把可入库的观察写入高频数据（调用 `vi_ingest()`） |
| ③ 自检 · 采集健康检查 | 每天 19:10 | 回写健康状态（调用 `vi_selfcheck()`），有异常时发站内信 |
| ④ 手动采集 · 按钮触发 | 按按钮时 | “采集运行”新增一行即触发，依次做 ①②③ 的事 |

**报表更新**（季报、半年报、年报出来后跑一次）：`python3 framework/tools/fin_stmt.py all <公司代码>` 用 akshare 更新三大报表；来源方式为“报表计算”的指标（收入、毛利率、应收、减值、带息负债等）随之自动更新，不用另外录。

**手动录入**：经营简报、分红方案、业绩会口径等没有稳定接口的数，在「数据」里给指标录一行（期间、口径、数值、同比）。「数据底稿 / 指标」的“状态”会自动变成已更新、待更新或未记录。

抓取失败（连不上网站）和校验失败（拿到响应但解析不出来）分开显示；“原始采集记录”的“抓取情况”列写着 HTTP 状态或连接错误原文。

## 历史年度、资产项目与数据出处（2026-10-26）

- **历史年度改为结果表**：只填口径说明、主要来源、备注；20 列数值全部来自这家公司对应的指标（指标的“模型字段”）。报表科目按报表公式算（期间数取全年，余额取年末）；追溯调整或口径不同的年份在「数据」里录调整值，录了以录的为准；业务量、折旧、分红、每股股息等报表外的数是披露指标。原手录 969 个数中 648 个改由报表算出，321 个保留为录入值；长江电力 2014—2022 年另由报表补出 49 格，追溯调整年份中口径不一致的 22 格明确留空。逐格核对与原值一致（舍入 0.006 亿元以内），自动检查结果不变。
- **资产估值与调整引用指标**：现金、借款、带息负债、对外上市股权、少数股东权益等是报表科目或已有指标的项目，关联“取数指标”，取该指标在“截至”日的值，不再手抄金额（与手填金额二选一）。腾讯音乐现金及定期存款由 442.22 统一为报表口径 442.94 亿元，分部加总每股 +0.02 元；其余估值不变。
- **「数据」的出处只记一处**：删去逐行重复的“采集地址”“使用边界”；自动采集的数据关联原始采集记录，历史补数关联 9 份新建的来源文档，水文数据的使用限制写进指标说明。
- **性能**：报表计算结果与历史年度数值由数据库自动维护缓存（`vi_stmt_cache`、`vi_fin_history_cache`，报表、公式、相关数据或口径变化时自动刷新）；自动检查由 2.8 秒降到 0.5 秒。
- **种子**：三大报表原值从各公司 `data/fin_stmt.json` 写入；历史年度、资产引用、调整值写在 `data/data_layer.json`，由 `framework/data_layer_seed.py` 写入。空库重建与在线库的估值、自动检查一致，三大报表与历史年度逐行一致。迁移：`2026-10-26h_observation_provenance.sql`、`2026-10-26i_history_assets.sql`（`framework/migrate_provenance.py`、`framework/migrate_history.py` 生成）、`2026-10-26j_history_scope_blanks.sql`；`tools/fin_stmt.py` 去掉了与历史年度的对账（已直接由报表计算）。

## 数据底稿：四样东西（2026-10-26）

数据底稿只放四样东西，任何内容只存一处：

| 形态 | 放哪里 | 规则 |
|---|---|---|
| 数 | 业务数据（指标＋数据）、财务数据（季度三大报表原值） | 有期间、会重复出现的数字只存在这里 |
| 话 | 重要事实 | 只写文字；数字是某个指标某一期的值时，关联“相关指标”。表上不再有“数值、单位” |
| 关注 | 指标页的“重点跟踪”标签 | 不单独建表：假设依据的“跟踪指标”、风险的“预警指标”关联到指标，指标上自动显示最新值、下次应更新日期和状态（未记录／待更新／已更新） |
| 出处 | 来源文档 | 事实、每期数据关联它；每个指标必须写“数据来源”（数据库约束 `vi_metric_source_required`） |

要盯一个新数：在假设依据或风险里关联指标（没有指标先在「指标」里建），为什么盯写在指标的“说明”里。没有指标的定性事项（诉讼、政策、项目进度）写成一句“持续跟踪：…（频率；来源：…）”，放在风险的“预警信号”，没有风险时放在假设依据的“事实层”。

迁移原 61 条跟踪事项：40 条挂到指标（新建 1 个指标：长江电力实现售电价）；21 条定性事项、7 条指标覆盖不全的部分写成“持续跟踪”句子；正文里 21 处跟踪事项编号换成名称。重要事实 13 条新关联指标，10 条推算值记进备注。原始记录存档在 `checks/data_layer_20261026/`（`watch_archive.json`、`fact_values_archive.json`）。估值 15 行、自动检查 95 行与迁移前完全一致。
