# 火山引擎部署预演

## 范围

这是独立的空库部署测试，不迁移本机尚在配置的价值投资数据。

- 服务器：`118.196.72.148`，目录 `/opt/nocobase-preview`。
- Compose 项目：`nocobase-preview`。
- NocoBase：`2.2.29-full`，与本机内核版本一致；full 镜像补充备份恢复所需数据库客户端。
- PostgreSQL：`16`，与本机数据库主版本一致。
- 远端仅监听 `127.0.0.1:13010`；数据库不发布主机端口。
- 通过 SSH 转发到这台 Mac 的 `http://127.0.0.1:18080`，与本机原系统的 `localhost:13000` 分开，避免独立实例的登录 cookie 混用。
- 为 2 GiB 内存服务器增加 2 GiB Swap，已写入 `/etc/fstab`。

## 启动测试访问

```sh
./preview-access.sh start
./preview-access.sh status
```

结束本机访问隧道：

```sh
./preview-access.sh stop
```

关闭隧道只会断开本机访问，不会停止云端应用。

部署配置模板：`preview-compose.yml`。应用密钥、数据库密码和测试管理员密码随机生成；远端位于权限为 600 的 `.env`，不写进仓库。

## 本地配置完成后的正式更新

1. 选定一个本地配置完成的时间点，在短暂停止写入的窗口创建一致性备份。
2. 备份须覆盖 PostgreSQL 的表、视图、函数、触发器等结构与数据，以及 NocoBase storage 中需要迁移的附件、页面资源、插件文件。
3. 为当时的云端实例备份，并将本地完整备份上传到服务器。
4. 在相同 NocoBase 内核版本和 PostgreSQL 主版本下恢复，检查插件是否与备份匹配。
5. 验证所有公司页、财务模型、图表、附件、管理员与 Dreamizer 登录/展示权限，再切换访问。
6. 若需要公开展示，再配置公网访问、域名和 HTTPS；当前隧道仅供本机验收。

这不是自动双向同步。完整恢复会以本地快照替换目标内容，云端测试数据和独立改动不应作为正式数据保留。若之后希望增量同步，需要另行设计更新流程。

本轮空库部署成功也不代表已验证整套业务数据恢复；实际工作台的恢复验收在本地快照确定后进行。
