## 设计原则

1. **没有隐式继承**：逐年假设每格都显式填写，不存在“空白＝沿用基准”。
2. **空白＝未知，不是 0**：例如现金桥接缺项时，现金支持价值不输出。
3. **派生值不手填**：单价、派息率、税率、同比、利息、归属折旧、每股价值、关注价都由公式计算。
4. **口径一致**：
   - 比率一律存小数，界面显示为百分比。
   - 金额单位是亿元。
   - 同比只在口径相同的相邻年份间计算。
5. **模型逻辑闭合**：
   - 利息＝平均带息负债×平均债务成本（债务滚动）。
   - 归母利润＝利润总额×(1−税率)×(1−少数股东占比)。
   - 价值按折现率从基准日滚动到今天，再和今天的股价比较。
   - 资产侧单独滚动（经营性长期资产、长期股权投资、带息负债、权益），平衡项＝其他净资产；它的年变化与现金桥接逐年一致，不影响利润和估值。
6. **不写死公司、年份、情景名或指标代码**：
   - 年份范围来自估值模型。
   - “基准情景”是情景表里的一个勾选项。
   - 股价指标在公司表里指定。
   - 采集用“解析器＋参数”配置。
7. **两种估值视角并列**：
   - 折现率视角：无风险利率＋风险溢价，回答“值多少”。
   - 要求收益率视角（默认 6%，可在驾驶舱调整）：回答“这个价格买进，年化回报是否达标”。

   隐含年化收益率与最高买入价都从今天起算现金流，两者等价。
8. **证伪可自动检查**：论点可以绑定“指标、条件、阈值、连续年数”，系统从历史年度自动判断是否触发。

## 分部加总估值（2026-10-22 新增）

股息贴现之外的第二种主估值方法。适合“经营业务＋大额现金与对外持股”的公司：

**核心业务盈利 × 合理倍数 ＋ 可用净现金 ＋ 对外投资（折后）− 少数股东权益与其他**

- **估值模型**新增四个字段：主估值方法（股息贴现/分部加总）、核心盈利年份、核心盈利调整（税后归母）、资产负债日。
- **情景**新增两个字段：新增投资回报率、合理倍数（手填）。合理倍数默认按 (1−g÷新增投资回报率)÷(r−g) 推导，与情景的折现率、永续增长联动。
- **分部估值项**（`sotp_item`）：现金、带息负债、经营所需现金、资金汇出成本、对外投资、少数股东权益、其他调整，每项有金额与折价。适用情景留空＝全部情景，同编号可按情景写专属行。
- **分部加总估值**（`vi_sotp`，只读）：核心盈利取预测计算里该年的“利润总额−其他净贡献＋利息”乘以归母比例，所以利息收入和财务费用不会和现金、负债重复计价。它还给出：
  - 市场隐含核心倍数；
  - 股价币种的每股价值；
  - 与股息贴现的差距。
- **驾驶舱**：主估值为分部加总时，关键读数先显示分部加总卡片，带“试算倍数”滑块；另有构成、倍数→价值、合理倍数与隐含倍数三张图。
- **自动检查**增加到 16 项。C16 对照两种方法，基准相差超过 25% 时提示。
- **在线库迁移**：`sql/migrations/2026-10-22_sotp.sql`。

## 经营分部估值（2026-10-23 新增）

分部加总的扩展：一家公司里处在不同发展阶段的业务，各用一种方法估值，写在「预测与估值 / 经营分部估值」（`sotp_segment`）。

估值模型的“核心盈利年份”留空时，分部加总不读预测计算，经营业务全部来自经营分部；两者也可以同时用。小米集团是第一个使用者。

| 方法 | 适合 | 价值（折回资产负债日 D） |
|---|---|---|
| 盈利×倍数 | 成熟或周期业务 | 正常化盈利 × 倍数 ÷ (1+r)^τ ＋ 期间现金流 ÷ (1+r)^(τ/2) |
| 稳态折现 | 成长业务 | 同上，盈利取稳态年份，倍数是退出倍数，折现率可单独加执行风险 |
| 承诺投入 | 投入期业务 | −(剩余金额÷n)×(1−t)×[1−(1+r)^−n]÷r − 承诺期后年成本×(1−t)÷(r−g)÷(1+r)^n |
| 直接估值 | 有可比估值、还没有可靠利润的业务 | 填写的整体价值（已含未来投入与回报，不折现） |

各项参数的口径：

- **盈利**＝收入 × 经营利润率 × (1−税率) × 归母比例。
- **τ**＝盈利年份上一年 12 月 31 日距 D 的年数（不足 0 记 0）。例如 D＝2026-06-30、盈利年份 2027 年时 τ＝0.5 年。（2026-10-23 晚更正：此前这里写成“第一个完整年度不折现”，公式本身一直是按 0.5 年折现。）
- **倍数**手填优先，否则按 (1−g÷新增投资回报率)÷(r−g) 推导；g、新增投资回报率、r 留空时取情景的值。
- **期间现金流**是 D 到盈利年份年初之间的税后累计现金流，按期中折现；负数＝还要投入。
- **情景专属行**：适用情景留空＝所有情景；同编号可按情景另写一行（与分部估值项相同）。
- **计算视图**：
  - `vi_sotp_segment_val`：情景 × 分部，算出每个情景下各分部的价值。
  - `vi_sotp_segment_calc`：界面计算列。适用全部情景的行按基准情景显示，并注明数值所属情景。
- **分部加总估值**新增以下输出：
  - 经营分部合计；
  - 成熟、成长、投入期、直接估值业务价值；
  - 成熟业务采用倍数；
  - 市场隐含成熟业务倍数：其余部分按本模型取值时，市值对应的成熟业务倍数；
  - 市场隐含成长业务价值；
  - 概率加权每股价值：情景表新增“情景概率”，各情景都填了才计算。
- **自动检查 C17**：
  - 有经营分部而基准情景算不出价值，结果为“阻断”；
  - 情景概率合计不是 100%，或成长业务超过股权价值 40%，结果为“提示”。
- **C16**：没有核心盈利时，改为对照成熟业务倍数与市场隐含成熟业务倍数。
- **驾驶舱**：
  - 有经营分部时，分部卡片显示成熟、成长、投入期（或直接估值）业务，以及市场隐含倍数与隐含成长价值；投入期、直接估值两列只在有对应分部时出现；
  - “试算倍数”改为试算成熟业务的倍数；
  - 新增“基准情景价值构成（逐项）”图；
  - 分部加总、适配度、壁垒、产业链、竞争对手、辩论这些通用图，只在这家公司有对应内容时才放进驾驶舱（`build_overview.content()`），还没填的公司不会出现空图。
- **在线库迁移**：`sql/migrations/2026-10-23_sotp_segment.sql`（新表、情景概率列，并一次性清理腾讯音乐种子早先留下的 15 条孤儿分部估值项）；`2026-10-23b_direct_value.sql`（“直接估值”方法的列）。

## 必须知道的坑（都已在脚本里处理）

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面或驾驶舱卡几十秒 | PostgreSQL JIT 编译多层视图的超大查询计划 | `ALTER DATABASE nocobase SET jit = off`（已执行；新库需重做） |
| 重启后 NocoBase 无法启动，报 `Target model … has no primary key attribute` | 视图集合的关联字段在目标视图主键加载前就被绑定 | 关联字段带 `options.source`，推迟到所有视图加载后再绑定（`register.mark_relation_source()`） |
| 生成页面报“description review” | UI 生成器把字段说明当作表单行为指令 | 先生成页面，再写字段说明；`rebuild()` 会自动先清空、后恢复 |
| 重建页面后详情弹窗没变 | 第一次生成时保存了弹窗模板，之后会被复用 | 先删页面，再删 `vi_` 弹窗模板，然后重建 |
| 只读报表出现新增、编辑、删除按钮 | applyBlueprint 自动补齐默认按钮 | `strip_write_actions()` 在生成后移除 |
| 字段名 `item` 报重复 | 与页面生成器内部的 key 冲突 | 改名为 `line_item` |
| 驾驶舱 JS 调 `workflows:execute` 被页面生成器拒绝 | RunJS 的 `ctx.request` 只允许增删改查类动作 | 按钮改为在“采集运行”表新增一行，由集合事件工作流 ④ 执行 |
| 工作流执行过一次后改不了配置 | NocoBase 锁定已执行的版本 | `python3 build_workflows.py --upgrade`：自动建同 key 新版本（设为当前）再改节点；入库、自检逻辑放在 SQL 函数里，改逻辑不用动工作流 |
| 中债页面解析错列 | PostgreSQL 正则的贪婪性由第一个量词决定 | 表头与数据行用字符串切片，再按“10年”所在列取值 |
| 新浪期货采集返回 403 | 新浪行情接口校验 Referer | 采集工作流统一带 `Referer: https://finance.sina.com.cn/`（腾讯、中债、长江水文网带上也正常） |
| 建菜单分组后，前面建的页面在 pages_state.json 里“丢了” | 写分组 id 时用了建分组前读到的旧状态覆盖文件 | `ensure_group()` 写之前重新读取（已修复）；页面本身不受影响，可按菜单补回记录 |
| 在公司菜单里新增的记录没出现 | 页面按“公司”过滤，表单里没选公司 | 新增时“公司”选这家公司（估值模型下的表选对应模型） |
| 迁移改名、加列后，详情弹窗里新字段排在最后（论点页的自动检查跑到正方立论前面） | NocoBase 按字段的 sort 排序，新列默认排最后 | `register.reorder_fields('<表代码>')` 按 spec 顺序重排，再 `build_pages.rebuild('<表代码>')`、`sort_menu()` |
| 表格页改了字段但详情弹窗没变 | 弹窗模板按集合复用，多家公司共用 | `build_pages.rebuild('<表代码>')` 会删掉所有公司的同名页面、删模板、再重建 |
| 编辑表单的关联下拉里混进别家公司的记录 | 弹窗模板五家共用，下拉默认列全表 | `python3 scope_selects.py`：按表单里选的公司（或所选模型/指标的公司）过滤，指标另加宏观；`build_pages.py` 和 `rebuild()` 末尾自动执行 |
| 没有 Wind 时取不到 10 年以上的完整报表 | Wind 积分不足，岗底斯结构化接口只覆盖近三年 | 东方财富 F10 接口（`emweb.securities.eastmoney.com/PC_HSF10/NewFinanceAnalysis/{lrb,zcfzb,xjllb}AjaxNew`，带 Referer）一次最多 5 个报告期，可取 2013 年以来全部科目；分红用 `datacenter.eastmoney.com` 的 RPT_SHAREBONUS_DET |
| `nb` 命令返回 401“Your session has expired” | CLI 保存的登录令牌过期（register.py、build_*.py 都会失败） | `nb env auth local` 重新登录（本机默认管理员账号）；想不过期可在「设置 → API 密钥」建密钥后用 `-a token` |
| 港股或美股公司的估值和股价对不上 | 记账币种是人民币，股价是港元/美元 | 公司表填“股价汇率指标”（`tencent_fx` 采集）；港股报价日期是 `2026/10/22 16:08:42`，`tencent_quote` 已改为只取数字 |

## 数据底稿：四样东西（2026-10-26）

数据底稿只放四样东西，任何内容只存一处：

| 形态 | 放哪里 | 规则 |
|---|---|---|
| 数 | 业务数据（指标＋数据）、财务数据（季度三大报表原值） | 有期间、会重复出现的数字只存在这里 |
| 话 | 重要事实 | 只写文字，关联来源文档；表上没有数值字段，数字的趋势看「重点指标」 |
| 关注 | 指标页的“重点跟踪”标签 | 不单独建表：假设依据的“跟踪指标”、风险的“预警指标”关联到指标，指标上自动显示最新值、下次应更新日期和状态（未记录／待更新／已更新） |
| 出处 | 来源文档 | 事实、每期数据关联它；每个指标必须写“数据来源”（数据库约束 `vi_metric_source_required`） |

要盯一个新数：在假设依据或风险里关联指标（没有指标先在「指标」里建），为什么盯写在指标的“说明”里。没有指标的定性事项（诉讼、政策、项目进度）写成一句“持续跟踪：…（频率；来源：…）”，放在风险的“预警信号”，没有风险时放在假设依据的“事实层”。
